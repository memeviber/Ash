# Release Notes

## Ash ownership and memory-safety release

This repository snapshot adds a Bootstrap-first static move/borrow checker for dynamic arrays and carries the corresponding ownership behavior into the Host compiler. The checker is intentionally scoped and explicit: `TDynArray` values are owning, recognized ownership transfers move the source, direct owner copies are rejected, address-taking records scoped borrows, and mutation, release, or move is forbidden while a borrow remains active.

### Added

The Bootstrap source now tracks per-variable ownership, moved state, borrow counts, and borrow provenance. Scope exit and pointer reassignment unwind borrow state. Dynamic-array arguments are consumed when passed to owned parameters, `array_free` consumes its owner, pointer returns cannot expose a local borrow, and error 33/34/35/37/38/40 are surfaced through Bootstrap diagnostics. The Host typechecker implements the corresponding `owned`, `moved`, `borrow_counts`, and `borrow_sources` state transitions and rejects the same ownership-invalid programs.

The new ownership corpus contains one valid fixture and five negative fixtures covering use-after-move, double-free, mutation while borrowed, borrow escape through return, and implicit owner copy. The dedicated `scripts/run_ownership_stress.sh` runner builds both compiler paths, requires strict GCC acceptance for valid generated C, runs the valid fixture under ASan and UBSan with leak detection, compares Host/Bootstrap runtime output, requires both compilers to reject every negative fixture, and invokes the existing regression, stress, adversarial, conformance, and fixed-point suites.

### Validation

The ownership valid fixture is accepted by both compilers and prints the identical output `7 8 41 41`. All five negative fixtures are rejected by both compilers with nonzero status. The valid generated C passes `-std=c11 -Wall -Wextra -Wpedantic -Wconversion -Wshadow -Werror`, and the sanitizer execution reports no AddressSanitizer, UBSan, or LeakSanitizer diagnostics.

The complete regression, stress, adversarial sanitizer, conformance, and fixed-point suites pass through the ownership runner. The Bootstrap generated C remains fixed-point stable: the next generation is byte-identical to the prior generated C and passes the same strict GCC flags.

### Generated-C comparison

For `test/stress/move_borrow_valid.ash`, the C generated by the pre-checker Bootstrap compiler and the C generated by the ownership-enabled Bootstrap compiler are both 9,687 bytes and have the same SHA-256:

```text
e21ef2547e65b93724b28ab20e35bba81541820da25982783cb7eb1ea258a692
```

The unified diff is empty. This is the expected result for a compile-time checker: valid programs retain the existing emitter output, while invalid ownership programs are rejected before C emission.

### Repository work

The canonical Bootstrap source and production C artifact are synchronized with the ownership checker. The Host OCaml checker and emitter mirrors are updated, and the new ownership fixtures, runner, audit, and release notes are included in the repository layout. Generated build directories, temporary logs, and validation binaries remain excluded from the clean ZIP package.
